## 处理事件回调与值变化

UI Toolkit 中的事件机制与 HTML 事件相似。事件发生时，UI Toolkit 会把它发送给目标视觉元素，以及视觉树中传播路径上的所有元素。

事件处理顺序如下：

1. 从根元素向下到事件目标，依次执行各元素上的事件回调——这是分发过程的 **trickle-down（捕获/下行）阶段**。
2. 从事件目标向上到根元素，依次执行各元素上的事件回调——这是分发过程的 **bubble-up（冒泡/上行）阶段**。

事件沿传播路径移动时，`Event.currentTarget` 属性会更新为当前正在处理该事件的元素。在事件回调函数中：

- `Event.currentTarget`：注册了该回调的视觉元素。
- `Event.target`：最初发生该事件的视觉元素。

更多细节参见“Dispatching events（事件分发）”。



### 注册事件回调

你可以注册事件回调，为已有类的某个实例定制行为，例如响应某个文本标签上的鼠标点击。注册方式是直接在元素上调用 `RegisterCallback()` 方法。

传播路径上的每个元素（目标元素除外）都可能收到事件两次：一次在 trickle-down 阶段，一次在 bubble-up 阶段。

对于不会传播到目标之外的事件，只会执行目标元素上的回调，但两阶段的顺序依然适用：用 `TrickleDown.TrickleDown` 注册的回调会先于用默认值 `TrickleDown.NoTrickleDown` 注册的回调执行。

如果你希望父元素先于其子元素做出响应，可以这样用 `TrickleDown.TrickleDown` 选项注册回调：

```csharp
using UnityEngine;
using UnityEngine.UIElements;

...
VisualElement myElement = new VisualElement();

// 为 trickle-down 阶段注册回调
myElement.RegisterCallback<PointerDownEvent>(MyCallback, TrickleDown.TrickleDown);
...
```

要为某个具体的视觉元素添加自定义行为，就在该元素上注册事件回调：

```csharp
// 为 pointer down 事件注册回调
myElement.RegisterCallback<PointerDownEvent>(MyCallback);
```

回调函数的签名如下：

```csharp
void MyCallback(PointerDownEvent evt) { /* ... */ }
```



**如果事件由其子元素处理，你需要先用 `Q()` 方法找到该子元素，再在它上面注册回调**。下面的例子在滑条（Slider）的拖拽容器元素上注册回调，以处理滑条的 pointer up 事件。这里必须注册在拖拽容器而不是滑条本身，因为拖拽容器在 pointer down 事件期间会捕获指针，从而成为下一个 pointer up 事件的唯一接收者：

```csharp
var dragContainer = slider.Q("unity-drag-container");
dragContainer.RegisterCallback<PointerUpEvent>(evt => Debug.Log("PointerUpEvent"));
```

> **注意** 同一个事件可以注册多个回调，但同一个回调函数在同一事件、同一传播阶段上只能注册一次。 要从 `VisualElement` 上移除回调，调用 `myElement.UnregisterCallback()` 方法。 关于如何从 MonoBehaviour 中访问视觉元素，参见“Get started with runtime UI”。



### 向事件回调传递自定义数据

你可以随回调一起传递自定义数据，方法是在注册回调时进行扩展。下面的例子为 `PointerDownEvent` 注册回调，并向回调函数传递自定义数据：

```csharp
// 把用户数据一并传给回调
myElement.RegisterCallback<PointerDownEvent, MyType>(MyCallbackWithData, myData);
```

回调函数的签名如下：

```csharp
void MyCallbackWithData(PointerDownEvent evt, MyType data) { /* ... */ }
```



## Manage the value of a control 管理控件的值

UI 控件使用 `value` 属性保存其内部状态数据。例如：

- `Toggle` 保存一个布尔值，在开关切换时改变。
- `IntegerField` 保存一个整数，即该字段的值。

**获取控件的值**有两种方式：

1. 直接从控件读取：`int val = myIntegerField.value;`
2. 监听控件发出的 `ChangeEvent`，在变化发生时处理。需要这样注册回调：

```csharp
// RegisterValueChangedCallback 是 RegisterCallback<ChangeEvent> 的简写。
// 它对实现了 INotifyValueChange 接口的 VisualElement 约束了正确的 T 类型。
myIntegerField.RegisterValueChangedCallback(OnIntegerFieldChange);
```

回调函数的签名如下：

```csharp
void OnIntegerFieldChange(ChangeEvent<int> evt) { /* ... */ }
```

`ChangeEvent` 会沿视觉树传播。如果你在容器或其他祖先元素上注册回调，同一个处理函数可能会被子控件引发的值变化调用；用 `evt.target` 判断是哪个控件派发了事件，用 `evt.currentTarget` 判断回调注册在哪个元素上。在值变化处理函数中，应避免以会触发嵌套值变化的方式去更新无关控件，除非你确实想要这种流程。详见“Change events”和“Dispatch events”。

**修改控件的值**有两种方式：

1. 直接赋值：`myControl.value = myNewValue;`——这会触发一个新的 `ChangeEvent`。
2. 使用 `myControl.SetValueWithoutNotify(myNewValue);`——这不会触发新的 `ChangeEvent`。

更多细节参见“Change events”。

## 要点速记

| 主题                       | 关键点                                                       |
| -------------------------- | ------------------------------------------------------------ |
| 事件传播                   | 先 trickle-down（根→目标），再 bubble-up（目标→根）          |
| `currentTarget` / `target` | 前者是注册回调的元素，后者是事件原始发生元素                 |
| 注册回调                   | `RegisterCallback<TEvent>(回调)`，父先于子需加 `TrickleDown.TrickleDown` |
| 子元素事件                 | 用 `Q()` 找到子元素再注册（如滑条的 `unity-drag-container`） |
| 传自定义数据               | `RegisterCallback<TEvent, TData>(回调, 数据)`                |
| 移除回调                   | `UnregisterCallback()`；同一回调同阶段只能注册一次           |
| 读值                       | 直接取 `value`，或注册 `RegisterValueChangedCallback`        |
| 写值                       | `value = x` 会触发 `ChangeEvent`；`SetValueWithoutNotify(x)` 不触发 |
