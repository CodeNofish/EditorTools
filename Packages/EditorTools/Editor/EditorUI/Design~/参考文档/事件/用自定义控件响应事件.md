## 内容摘要

本文介绍在实现**自定义控件**时如何响应 UI Toolkit 事件，主要有两条路径：**注册事件回调**，或**重写 `HandleEventBubbleUp` / `HandleEventTrickleDown` 虚方法**。文中对比了两者的差异（作用范围、性能、是否需要改动类本身），并给出重写示例与最佳实践（优先用 `HandleEventBubbleUp` 实现行为、如何停止事件冒泡）。

------

## 用自定义控件响应事件

学习如何用自定义控件响应事件。

如果你正在实现自定义控件，可以通过以下方式响应 UI Toolkit 事件：

- 注册事件回调
- 重写 `HandleEventBubbleUp` 或 `HandleEventTrickleDown` 虚方法

你选择哪种响应方式取决于具体场景。回调与虚方法重写之间的区别如下：

- 回调必须在类的实例上进行注册；而虚方法则需要修改类本身。
- 虚方法重写具有轻微的性能优势，因为在传播阶段不需要在回调注册表中进行查找。



### 重写 HandleEventBubbleUp 或 HandleEventTrickleDown 虚方法

虚方法重写对该类的所有实例都生效。对于一个重写了 `HandleEventBubbleUp` 或 `HandleEventTrickleDown` 的类，你仍然可以在它的实例上注册回调。

要重写 `HandleEventBubbleUp` 或 `HandleEventTrickleDown` 方法（或两者都重写），需要派生一个新的 `VisualElement` 子类。

当某个视觉元素子类的实例接收到事件时，`HandleEventBubbleUp` 和 `HandleEventTrickleDown` 会在该实例上执行。

下面的示例展示了如何自定义这些虚方法：

```csharp
override void HandleEventBubbleUp(EventBase evt)
{
    // 调用基类函数。
    base.HandleEventBubbleUp(evt);

    if (evt.eventTypeId == PointerDownEvent.TypeId())
    {
        // ...
    }
    else if (evt.eventTypeId == MouseUpEvent.TypeId())
    {
        // ...
    }
    // 更多事件类型
}
```

对于给定的类实例，在以下两种情况下执行自定义代码，效果是相同的：

- 在为 BubbleUp（冒泡）阶段设置的回调中
- 在 `HandleEventBubbleUp` 方法的重写中

在这两种情况下，如果你停止事件的传播，都会阻止在执行完当前目标的回调和方法重写之后对该事件的进一步响应。



### 最佳实践

以下是用自定义控件处理事件的最佳实践。

#### 实现行为

通常来说，要为你的元素实现行为，请使用 `HandleEventBubbleUp` 方法重写。

由于 BubbleUp（冒泡）是回调的默认传播阶段，你可以把回调中的任何代码移到 `HandleEventBubbleUp` 方法中，而不必担心改变代码执行的时机。

把行为实现为方法重写的好处包括：

- 方法重写不需要在回调注册表中进行查找。
- 没有注册回调的实例不会进入传播过程。

#### 停止事件传播

在回调或虚方法重写中处理事件时，你可以通过调用事件上的某个 `StopPropagation` 方法来阻止事件继续传播。例如，父面板可以在 trickle-down（捕获/下行）阶段停止传播，以防止其子元素接收到事件。

你无法阻止事件类内部的 `EventBase.PreDispatch()` 和 `EventBase.PostDispatch()` 方法的执行。

以下方法会影响事件传播：

- `StopImmediatePropagation()`：立即停止事件传播过程，阻止该事件的任何后续回调执行。
- `StopPropagation()`：在当前元素上的最后一个回调之后停止事件传播过程。这确保当前元素上的所有回调都会执行，同时阻止任何后续元素对该事件做出响应。

### 关键术语注释

1. **custom control** → 自定义控件：通过派生 `VisualElement` 等基类实现的自有 UI 控件。
2. **virtual method override** → 虚方法重写：在子类中重新实现基类虚方法，对该类所有实例统一生效。
3. **callback registry** → 回调注册表：UI Toolkit 用于查找元素上已注册回调的内部结构，重写虚方法可绕过这次查找。
4. **trickle-down / bubble-up** → 捕获（下行）阶段／冒泡（上行）阶段：事件分发的两个方向，前者根→目标，后者目标→根。
5. **StopPropagation / StopImmediatePropagation** → 停止冒泡／立即停止冒泡：前者在当前元素回调执行完后停止，后者立刻终止整个传播。
