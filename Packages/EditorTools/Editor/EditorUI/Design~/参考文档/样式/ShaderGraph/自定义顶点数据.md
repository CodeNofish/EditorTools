**内容摘要：** 本文介绍 UI Toolkit 的自定义顶点数据功能，允许开发者在面板中启用额外的 GPU 顶点通道（如法线、切线、额外 UV），在网格生成时写入自定义数据，并在 UI Shader Graph 中读取这些数据以实现更复杂的视觉效果。



# 自定义顶点数据

配置面板，在网格生成期间写入每个顶点的值，并在自定义 Shader Graph 中读取它们。

UI Toolkit 面板使用固定的 GPU 顶点布局：位置（position）、颜色（color）、主 UV 通道，以及少量用于裁剪、变换和其他渲染器状态的内部通道。使用 UI Shader Graph 编写的自定义着色器无法读取额外的输入，除非面板在 GPU 上为它们分配了存储空间。

**ExtraVertexChannels** 选项允许面板为每个顶点追加 TexCoord1、TexCoord2、TexCoord3、Normal（法线）和 Tangent（切线）的任意组合。自定义网格生成代码随后可以将值推送到这些通道中，而自定义 Shader Graph 则可以使用相同的语义（TEXCOORD1-TEXCOORD3、NORMAL、TANGENT）读取它们。

当你需要将数据传入着色器，而内置顶点布局不携带这些数据时，可以使用此功能——例如伪光照法线、切线空间变形，或用于程序化效果的额外每顶点参数。



## 在面板上启用通道

该选项位于运行时面板的 `PanelSettings.extraVertexChannels` 上，以及编辑器面板的 `IPanel.extraVertexChannels` 上。

在 **Panel Settings（面板设置）** 的检查器中，找到 **Buffer Management（缓冲区管理）** 下的 **Extra Vertex Channels（额外顶点通道）** 下拉菜单，并启用你需要的标志：

```csharp
// 运行时面板——在编辑时针对 PanelSettings 资源设置，或在运行时通过代码设置。
panelSettings.extraVertexChannels = ExtraVertexChannels.Normal | ExtraVertexChannels.TexCoord1;

// 编辑器面板——直接在 IPanel 上设置标志。
panel.extraVertexChannels = ExtraVertexChannels.Normal;
```

在面板开始渲染后更改通道集会重建面板的渲染链。运行时面板及其视觉树会被保留。

每个启用的通道会在 GPU 上为每个顶点增加 16 字节。除非面板上的着色器确实需要这些数据，否则请将此属性保留为 **None**。



## 为每次绘制提供通道数据

自定义网格生成在 `VisualElement.generateVisualContent` 回调中运行。在那里，分配一个 `UIMesh` 并通过 `MeshGenerationContext.DrawMesh(ref UIMesh, Texture)` 提交它。

有两种方式填充 `UIMesh`：

### 从临时分配器分配

最简单的方法是让 `MeshGenerationContext` 为你分配切片。分配器返回一个 `UIMesh`，其必需的 `vertices` / `indices` 切片按请求大小分配，外加你传入的掩码中每个通道的一个切片。你未请求的通道将返回为空的默认切片。

```csharp
void OnGenerateContent(MeshGenerationContext mgc)
{
    const int vertexCount = 4;
    const int indexCount = 6;

    mgc.AllocateTempMesh(
        ExtraVertexChannels.Normal | ExtraVertexChannels.TexCoord1,
        vertexCount, indexCount,
        out UIMesh mesh);

    for (int i = 0; i < vertexCount; ++i)
    {
        mesh.vertices[i] = new Vertex { position = ..., tint = Color.white };
        mesh.normal[i]   = new Vector3(0, 0, 1);
        mesh.uv1[i]      = new Vector4(i, 0, 0, 0);
    }

    mesh.indices[0] = 0; mesh.indices[1] = 1; mesh.indices[2] = 2;
    mesh.indices[3] = 0; mesh.indices[4] = 2; mesh.indices[5] = 3;

    mgc.DrawMesh(ref mesh);
}
```

此方法推荐用于大多数情况。切片在渲染器刷新当前重绘通道之前都有效，这总是在 `generateVisualContent` 返回之后。

### 自带数组

如果你已经在自己的 `NativeArray<T>` 中拥有通道数据（例如由上游 Burst 作业生成），则将每个数组分配到匹配的 `UIMesh` 字段并提交：

```csharp
void OnGenerateContent(MeshGenerationContext mgc)
{
    // 切片由调用者拥有。它们必须保持有效，直到下一个
    // MeshGenerationContext 刷新（当前重绘通道结束）。
    NativeSlice<Vertex>  vertices = m_VertexBuffer.AsSlice();
    NativeSlice<ushort>  indices  = m_IndexBuffer.AsSlice();
    NativeSlice<Vector3> normals  = m_NormalBuffer.AsSlice();

    var mesh = new UIMesh
    {
        vertices = vertices,
        indices  = indices,
        normal   = normals,
    };
    mgc.DrawMesh(ref mesh);
}
```

`UIMesh` 内部的切片在刷新时读取，而不是在 `DrawMesh` 返回时读取。`UIMesh` 中所有非空切片必须保持有效，直到下一个 `MeshGenerationContext` 刷新（当前重绘通道结束）。由 `AllocateTempMesh` 返回的切片由临时分配器的生命周期保证有效。



## 验证规则

`DrawMesh(ref UIMesh, …)` 在提交时强制执行两条规则。违反规则会通过 `Debug.LogError` 记录日志，违规数据会被丢弃——渲染器永远不会因每帧网格生成代码而抛出异常。

- **长度一致性**：每个非空的额外切片必须与 `vertices` 具有相同的长度。如果有任何不一致，整个绘制会被丢弃——索引可能会引用较短切片中不存在的顶点槽位。
- **通道一致性**：为面板未通过 `extraVertexChannels` 启用的通道提供切片是错误的。违规切片会从绘制中清除，其余绘制继续进行。面板没有该通道的 GPU 槽位——针对它编写的着色器无论如何都会读取未定义的数据。

在启用了额外通道的面板上进行绘制时不提供任何额外数据是可以的，仅提供已启用通道的子集也是可以的。在确实提供额外数据的绘制中，面板已启用但调用者留空的通道会在该绘制的流 1（stream-1）顶点槽位中填充零。完全不提供额外数据的绘制不会改动流 1 槽位——只有当绑定到这些顶点的着色器不读取流 1 时，这才有意义。



## 在 Shader Graph 中读取通道

在 UI Shader Graph 中，添加 **UV** 节点（通道 UV1、UV2 或 UV3）、**Normal Vector** 节点、**Tangent Vector** 节点或 **Bitangent Vector** 节点。它们会自动连接到 `VertexDescriptionInputs` 中的匹配通道以及生成的顶点着色器中的匹配语义。Shader Graph 编辑器接受 UI 材质上的 UV0-UV3；UV4 和 UV5 保留供内部渲染器使用。**Bitangent Vector** 节点由法线和切线派生，因此面板必须同时启用 Normal 和 Tangent 通道，它才能产生有意义的值。

将 **Normal Vector**、**Tangent Vector** 和 **Bitangent Vector** 节点的 **Space** 属性设置为 **Object**。UI Toolkit 在渲染期间不应用每元素的世界变换，因此其他空间选项会将值乘以不相关的矩阵，产生错误的数据。**Object** 会原样返回打包到顶点流中的值。

**重要提示** **Normal Vector**、**Tangent Vector** 和 **Bitangent Vector** 节点只能在 UI Shader Graph 的**顶点阶段**使用。要在片段阶段读取这些值，请将节点连接到顶点上下文中的 **Custom Interpolator** 块，然后在片段上下文中读取匹配的 **Custom Interpolator** 节点。

Shader Graph 资源不知道哪个面板会使用它。你有责任在每个托管 `VisualElement` 的面板上设置 `extraVertexChannels`，该 `VisualElement` 的网格数据会传入你的着色器。
