# **管理元素的最佳实践**

在 UI 中管理元素时，你可以采取以下措施来提升性能。

本页面介绍了管理可视化树中元素的最佳实践。



### 池化可复用的元素

元素池化是指保留那些之后可能重新创建的元素，而不是每次都通过 `new()` 创建新元素并在用完后丢弃。

当你为 `VisualElement` 实现自定义对象池时，需要完全掌控所有被池化的元素，并在将它们放回池之前进行重置。UI Toolkit 为事件（`EventBase`）等系统提供了内部池化以提升性能，但它并未为 `VisualElement` 提供内置池。如果你创建自己的池，必须自行处理清理工作。例如，如果你在某个元素上注册了事件回调，却在将其放回池时没有注销该回调，该回调将仍然存在。这会在元素被复用时导致不稳定、意外行为和内存泄漏。



### 保持可见元素数量较低

为了保持可视化元素数量较低，请尽可能使用 `ListView`。`ListView` 会对元素进行池化，并在用户滚动时循环利用元素。

你也可以实现类似 `ListView` 的自定义池化和回收机制，并使用以下方式管理可见区域：

- 使用 `GeometryChangedEvent` 来观察容器尺寸
- 使用 `VisualElement.layout` 属性来计算子元素的尺寸





### 隐藏元素的不同方式

当你使用 `VisualElement.RemoveFromHierarchy()` 将元素从层级中移除并消除对它的引用时，该元素会被垃圾回收。这会将 CPU 和 GPU 开销降至零，并释放大量内存。然而，重新创建元素并将其重新加载到层级中是一项缓慢且代价高昂的操作。为了避免这种情况，你可以预先在层级中创建元素，使用 USS 样式属性隐藏它们，仅在需要时显示。虽然应用样式通常更快，但如果你同时创建大量元素，可能会导致内存占用增加。

以下描述了隐藏元素的不同方式及其对处理器和内存使用的影响。请参考下表获取不同方式的总结：

#### 隐藏元素方式总结

| 方式                  | CPU/GPU 开销                             | 内存占用                          | 适用场景                                   |
| :-------------------- | :--------------------------------------- | :-------------------------------- | :----------------------------------------- |
| `visibility: hidden;` | CPU 持续评估样式；GPU 释放网格和渲染命令 | 保留样式和布局数据                | 需要保留布局空间，但可接受子元素覆盖可见性 |
| `opacity: 0;`         | CPU 持续评估样式；GPU 仍处理顶点着色     | 保留全部数据                      | 需要保留布局和交互，GPU 资源充足           |
| `display: none;`      | CPU 跳过渲染命令执行；无 GPU 开销        | 保留样式和布局数据                | 不需要布局空间，希望避免 GPU 开销          |
| 平移至视口外          | CPU 更新样式和布局；GPU 仍处理顶点       | 保留全部数据                      | 需要快速恢复显示，GPU 可接受额外顶点处理   |
| 从层级中移除          | 无持续开销                               | 释放样式、渲染命令和 GPU 网格内存 | 长期不用的元素，希望彻底释放资源           |

---



#### 使用 USS 样式 `visibility: hidden;` 隐藏

使用此方式时，后代元素可以覆盖 `visibility` 样式。

**单帧开销**

| 方面     | `visibility: hidden;`              | `visibility: visible;`             |
| :------- | :--------------------------------- | :--------------------------------- |
| 样式     | 为该元素及其后代评估，以传播可见性 | 为该元素及其后代评估，以传播可见性 |
| 布局数据 | 保留                               | 无                                 |
| 渲染命令 | 移除并释放                         | 重新创建并重新插入命令链           |
| 网格     | 安排释放                           | 重新细分                           |

**每帧行为**

| 处理器 | 方面     | 每帧行为                                                     |
| :----- | :------- | :----------------------------------------------------------- |
| CPU    | 样式     | 对该元素及其后代进行完整评估                                 |
|        | 布局数据 | 更新                                                         |
|        | 细分     | 影响极小，仅涉及模板遮罩网格（如适用）                       |
|        | 渲染命令 | 无绘制常规可见几何体的命令。但模板遮罩网格仍会被渲染，以推入或弹出模板缓冲区，确保潜在可见的后代被正确遮罩 |
| GPU    | 网格     | 对模板遮罩网格进行顶点和片段着色                             |

---



#### 使用 USS 样式 `opacity: 0;` 隐藏

使用此方式时，由于顶点着色器会处理所有元素，因此会对 GPU 产生一定影响。

**单帧开销**

| 操作          | 单帧开销                                                     |
| :------------ | :----------------------------------------------------------- |
| `opacity: 0;` | 首次将不透明度设置为非 1 的值时，UI Toolkit 渲染器会修改顶点以加速在 GPU 上应用不透明度。这会触发一次性的、极小的 CPU 开销。虽然通常可忽略不计，但如果元素拥有大量后代或需要修改的顶点很多，此开销可能会变得明显。除非该元素被从可视化树中移除并重新添加，否则不会再次产生此开销 |
| `opacity: 1;` | 无                                                           |

**每帧行为**

| 处理器 | 方面     | 每帧行为                                                     |
| :----- | :------- | :----------------------------------------------------------- |
| CPU    | 样式     | 对该元素及其后代进行完整评估                                 |
|        | 细分     | 正常运行并响应变化                                           |
|        | 渲染命令 | 执行                                                         |
| GPU    | 网格     | 顶点着色器的运行方式如同可见性设为 1，如果存在大量顶点需要处理，对于 GPU 受限的项目可能不利。三角形被移出屏幕，因此不会产生片段着色器开销 |

---



#### 使用 USS 样式 `display: none;` 隐藏

使用此方式时，元素的行为如同从布局树中移除，这可能会影响其他元素的布局。

**单帧开销**

| 方面          | `display: none;`               | `display: flex;`                               |
| :------------ | :----------------------------- | :--------------------------------------------- |
| 布局数据      | 可能重新计算其他元素的布局     | 处理待处理的布局变更                           |
| 渲染命令/网格 | 为受布局变更影响的元素重新生成 | 为受布局变更影响的元素重新生成；处理待处理变更 |

**每帧行为**

使用 `display` 样式隐藏可视化元素时，CPU 的每帧行为如下表所示。注意，此方式没有 GPU 开销。

| 方面     | 每帧行为                                                     |
| :------- | :----------------------------------------------------------- |
| 布局数据 | 保留，但可能失效且不再更新                                   |
| 渲染命令 | 虽然被保留，但在执行期间可以跳过。跳过的方式非常廉价，但并非完全免费。开销与命令数量成正比 |
| 网格     | 保留，但可能失效且不再更新                                   |

---



#### 平移至视口之外

你可以使用 `translate: -5000px -5000px;` 结合 `DynamicTransform` 使用提示，将元素移出视口。几何体保持完全活跃，因此将元素重新带回屏幕时 CPU 开销极小。然而，GPU 会继续处理顶点，具体是否可接受取决于场景。

**单帧开销**

变换被计算并上传到 GPU 内存，通常速度很快。

**每帧行为**

| 处理器 | 方面     | 每帧行为   |
| :----- | :------- | :--------- |
| CPU    | 样式     | 更新       |
|        | 布局数据 | 更新       |
|        | 绘制调用 | 执行       |
| GPU    | 网格     | 顶点被着色 |

---



#### 从层级中移除

当你使用 `VisualElement.RemoveFromHierarchy()` 方法将元素从层级中移除时，会释放 CPU 和 GPU 内存，从而消除所有计算开销。

**单帧开销**

| 方面          | 移除                           | 添加                           |
| :------------ | :----------------------------- | :----------------------------- |
| 样式          | 无                             | 对子树进行更新                 |
| 布局          | 无                             | 对子树及可能的其他元素重新计算 |
| 渲染命令/网格 | 为受布局变更影响的元素重新生成 |                                |
