在自定义组件库（Custom Controls Library）中通过 TSS 实现主题切换，核心思路是**“CSS 变量解耦 + 多主题文件映射 + 运行时动态替换”**。组件库本身不写死任何具体颜色或字号，而是只引用语义化的 CSS 变量，由不同的 `.tss` 文件为这些变量注入具体的值。

以下是完整的架构设计与实现步骤：

1. 制定组件库样式规范（CSS 变量解耦）

在组件库的基础样式表（如 `BaseComponents.uss`）中，所有视觉属性必须通过 `var(--变量名)` 引用，禁止硬编码颜色或尺寸。

- **定义语义化 Token。** 按照功能而非颜色命名变量，例如 `--color-bg-primary`、`--color-text-main`、`--border-radius-md`。
- **编写组件基础 USS。** 在组件库 USS 中绑定这些变量，并可在 `:root` 中提供一套默认兜底值（Fallback），防止外部未挂载主题时组件透明或报错。

css

```
/* BaseComponents.uss */
:root {
    --my-btn-bg: #333333;
    --my-btn-text: #FFFFFF;
}

.my-custom-button {
    background-color: var(--my-btn-bg);
    color: var(--my-btn-text);
    border-radius: var(--my-radius-md, 4px);
}
```

Use code with caution.

2. 构建多套主题 TSS 文件

在组件库的 Package 目录下创建多个 `.tss` 文件，每个文件代表一套独立的主题（例如 `LightTheme.tss` 和 `DarkTheme.tss`）。

- **导入基础组件样式。** 在每个主题 `.tss` 文件的顶部，通过 `@import` 引入组件库的 `BaseComponents.uss`，确保应用主题时组件基础结构样式也随之生效。
- **覆写变量值。** 在各自主题的 `:root` 选择器中，为同一套变量赋予不同的主题色值。

css

```
/* LightTheme.tss */
@import url("project://database/Packages/com.company.ui/Styles/BaseComponents.uss");

:root {
    --my-btn-bg: #F0F0F0;
    --my-btn-text: #1A1A1A;
}
```

Use code with caution.

css

```
/* DarkTheme.tss */
@import url("project://database/Packages/com.company.ui/Styles/BaseComponents.uss");

:root {
    --my-btn-bg: #222222;
    --my-btn-text: #EEEEEE;
}
```

Use code with caution.

3. 运行时实现动态主题切换

在游戏或应用运行时，有三种主要方式可以实现组件库的动态换肤，适用于不同规模的项目：

| 切换方式                      | 实现原理                                                     | 适用场景                                   | 优缺点                                                       |
| ----------------------------- | ------------------------------------------------------------ | ------------------------------------------ | ------------------------------------------------------------ |
| **替换 PanelSettings 的 TSS** | 通过代码修改 `panelSettings.themeStyleSheet = targetTss;`    | 全局统一换肤（最推荐、性能最高）           | 整个 Panel 瞬间切换，但需在运行前把 Package 里的 TSS 引用到脚本或 Addressables 中 |
| **根节点切换主题 Class**      | 将所有主题变量写在同一个 TSS 的不同类下（如 `.theme-dark`），运行时在 `rootVisualElement` 上增删类名 | 局部换肤（如页面内部分区域深色、部分浅色） | 无需切换资源引用，但所有主题变量会同时驻留内存               |
| **运行时合并 TSS 资源**       | 业务项目新建 `AppMain.tss`，用 `@import` 继承组件库的 TSS，再通过代码切换 `AppMainLight.tss` 和 `AppMainDark.tss` | 业务层需要扩展或魔改组件库主题             | 兼顾组件库升级与业务定制，扩展性最好                         |

**全局切换代码示例：**

csharp

```
using UnityEngine;
using UnityEngine.UIElements;

public class ThemeManager : MonoBehaviour
{
    [SerializeField] private UIDocument uiDocument;
    [SerializeField] private ThemeStyleSheet lightTheme; // 拖入 Package 中的 LightTheme.tss
    [SerializeField] private ThemeStyleSheet darkTheme;  // 拖入 Package 中的 DarkTheme.tss

    public void SwitchToDark()
    {
        if (uiDocument != null && uiDocument.panelSettings != null)
        {
            uiDocument.panelSettings.themeStyleSheet = darkTheme;
        }
    }
}
```

Use code with caution.

4. 组件库打包与使用注意事项

- **打包资源防丢失。** Package 中的 `.tss` 和 `.uss` 不会自动打入构建包（Build），必须在业务项目中通过 `PanelSettings`、ScriptableObject 配置表或 Addressables 显式引用它们，Unity 才会将其编译进最终包体。
- **自定义控件构造函数清理。** 在编写 C# 自定义控件（如继承 `VisualElement` 或 `UxmlElement`）时，仅在构造函数中添加语义类名（`AddToClassList("my-custom-button")`），切勿在 C# 代码中通过 `style.backgroundColor` 修改内联样式，因为内联样式的优先级高于 TSS，会导致主题切换失效。

你的自定义组件库需要支持 **全局统一切换** 还是 **局部区域独立主题**（例如弹窗用浅色、主界面用深色）？我可以为你提供对应的 C# 管理器代码或 USS 架构模板。
